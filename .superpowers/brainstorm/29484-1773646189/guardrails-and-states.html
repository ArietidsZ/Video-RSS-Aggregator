This section defines how each setup step communicates readiness, blocking issues, next actions, and advanced controls.

Completed

The step is visibly done, but still editable. The flow nudges forward while preserving user confidence and recoverability.

Interaction rules

Rules we add

  • Diagnostics do not auto-run on page load; the user explicitly starts the first check
  • Each step gets plain-language status: blocked, ready, running, complete
  • Raw JSON moves behind a details toggle; the default view uses human-readable summaries
  • Advanced config fields stay collapsed until prerequisite checks pass

Rules we avoid

  • No silent failure states buried in a log panel
  • No giant status dump before the user understands what they are checking
  • No forcing a full-page reload to refresh diagnostics
