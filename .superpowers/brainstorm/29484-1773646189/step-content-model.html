Section 3: What each step contains

This section defines the content model for the four-step setup flow using the existing backend surfaces.

Step 1 · Install prerequisites
Dependency checklist from diagnostics
Per-tool status cards: Python, FFmpeg, FFprobe, yt-dlp, Ollama
Fix instructions and re-check button
Continue only when required checks pass

1. Install prerequisites

Uses `GET /setup/diagnostics` as the main source of truth. Focus is on dependency readiness, not raw output logs.

Step 2 · Build configuration
Mode switch: Basic / Advanced
Basic fields: bind, storage, Ollama URL, model priority
Advanced tuning collapsed by default
Generated .env preview + copy action + quick commands

2. Build configuration

Starts from `GET /setup/config`, but shows a beginner-safe subset first. The full env block and quick commands stay visible as outputs, not as the primary editing surface.

Step 3 · Verify runtime
Connection summary: Ollama reachable / not reachable
Model list and missing-model warnings
Bootstrap action with progress / completion message
Show runtime details only on demand

3. Verify runtime

Uses `GET /runtime` and `POST /setup/bootstrap`. It explains whether the system can actually run, instead of just dumping a large JSON payload.

Step 4 · First processing run
Sample source prefilled + title override
Expectation setting: this may take a while
Human-readable result summary: title, frames, transcript, model used
Expandable raw response details

4. First processing run

Uses `POST /process` to prove the full path works. Success is framed as confidence-building evidence, not just a blob of output.

Recommended defaults

Beginner-first defaults

  • Basic mode hides budget ratios, scene thresholds, and retention knobs at first
  • Quick commands from config are surfaced as copyable helpers
  • Each step shows one success criterion before allowing the next step

Not in the first view

  • No 20-field wall before the user knows what matters
  • No giant raw JSON panes as the default reading experience
